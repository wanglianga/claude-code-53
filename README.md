# 口腔诊所正畸复诊排期与矫治器异常平台

## 原始需求

> 开发口腔诊所正畸复诊排期与矫治器异常平台，可使用 Next.js、NestJS 和 PostgreSQL。患者建档时，诊所记录口扫、面像、X 光片、牙周情况、治疗方案、收费阶段、预计周期和医生负责关系。平台根据患者矫治器副数、附件粘接、拔牙或片切计划、医生出诊、椅位资源和患者时间生成复诊排期。患者到诊后，护士核验佩戴时长、口腔卫生、附件脱落、牙套丢失、疼痛不适和付款阶段；医生记录复诊结论、是否进入下一副、是否重启方案或追加拍片。若患者临时延期、矫治器断裂、附件多次脱落、牙齿移动不达标、医生请假或付款逾期，平台要把患者、医生、护士、技工所和财务串在同一治疗计划里处理。每次复诊的影像、医嘱、材料、费用、下次预约和异常处理会回到患者长期档案，用于判断疗程是否延误、是否需要重启制作和是否影响最终保持器交付。平台还要把患者自述、医生病历、护士操作、技工所发货、收费节点和影像版本固定在同一治疗阶段，防止患者跨医生复诊或换诊所咨询时无法解释当前方案。对隐形矫治、固定托槽和儿童早矫，平台要允许不同复诊节奏和材料规则共存，同一患者换方案时也能保留历史判断。

## 技术栈与架构

- **前端**：Next.js 14（App Router，standalone 输出），通过 `/api/*` 重写反向代理到 API，浏览器只需访问 Web 一个端口
- **后端**：NestJS 10 + Prisma 5，JWT 鉴权 + 角色守卫（管理员/医生/护士/前台/财务/技工所）
- **数据库**：PostgreSQL 16（仅 compose 内部网络，不发布宿主端口）
- **部署**：`docker compose up -d` 一键启动（db / api / web 三服务，应用镜像多阶段构建、非 root 运行、内置 HEALTHCHECK）

```
浏览器 ──CC_PUBLISH_PORT──> web(Next.js:3000) ──/api/*──> api(NestJS:4000) ──> db(PostgreSQL:5432)
                              （唯一发布端口）        （内部网络）            （内部网络）
```

## 一键启动

```bash
cp .env.example .env        # 可选；评审环境已注入 CC_PUBLISH_PORT，无需手动配置
docker compose up -d --build
```

- 首次启动时 API 容器会自动执行 `prisma db push` 建表并写入幂等种子数据（演示患者/方案/预约/异常/收费/技工单）。
- 验证端口：`docker compose port web 3000` 获取宿主映射端口（等于 `CC_PUBLISH_PORT`），浏览器访问 `http://localhost:<端口>`。
- 健康检查：`docker compose ps` 三个服务均为 `healthy/running`；API 探针 `GET /api/health`，Web 探针 `GET /healthz`。
- 停止：`docker compose down`（加 `-v` 可同时清空数据卷）。

> 验证方式说明：本项目以「宿主 `docker compose up -d` 后服务健康 + 关键业务流可在浏览器走通」为验证通过标准，不依赖在评审容器内安装任何 SDK。

## 关键业务流（建议演示路径）

1. **建档**：患者档案 → 新患者建档（牙周情况、负责医生）→ 制定方案（类型/副数/附件/拔牙/片切/预计周期/收费阶段）。
2. **排期**：预约排期 → 智能排期 → 选患者/时间偏好 → 计算槽位（医生出诊 × 椅位 × 冲突避让）→ 点击槽位预约。同一患者只能约到方案负责医生，防止跨医生复诊。
3. **复诊**：预约列表「到诊」→ 复诊台 → 护士提交核验（附件脱落 ≥3 累计自动立案；牙套丢失自动立案+补制技工单；付款核验触发逾期扫描）→ 医生填写结论（进入下一副/重启方案/追加拍片/材料/医嘱）→ 提交后自动按复诊节奏预约下次。
4. **异常协同**：异常看板按角色生成任务（医生评估、技工所补制、前台改期、财务催收），处理完毕结案并评估疗程影响天数。
5. **医生请假**：预约排期 → 请假管理 → 登记请假（自动检出受影响预约并逐一立案）→ 前台「一键改期」。
6. **长期档案**：患者详情页 8 个标签页（概览/方案链/影像版本/复诊记录/收费/技工/异常/时间轴），所有事件锚定治疗阶段；疗程延误评估 = 异常影响天数 + 预计结束逾期天数。

## 设计要点

- **阶段锚定**：治疗阶段（TreatmentStage）是骨架，预约、复诊记录、影像版本、收费节点、技工单、材料、异常、时间轴事件全部外键锚定到阶段，换诊所/跨医生咨询时可完整还原当前方案上下文。
- **方案链**：换方案不删历史，旧方案置 `SWITCHED` 并挂到 `parentId` 链上，版本号递增；转诊（更换负责医生）必须填原因并写入时间轴。
- **三类方案共存**：隐形/固定/早矫各自默认复诊节奏（10/5/6 周）与材料规则，可按方案覆盖；隐形按每 10 副自动划分治疗阶段。
- **异常联动**：护士核验、医生结论、付款到期、医生请假、患者延期等业务动作会自动立案并给对应角色生成待办任务，结案时累计疗程影响天数用于延误评估。
